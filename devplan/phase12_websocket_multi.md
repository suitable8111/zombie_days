# 개발 지시서: Zombie Days - 웹소켓 기반 멀티플레이 아키텍처 설계 (Phase 12-1)

우리는 Itch.io(Pygbag 환경)에서 브라우저 기반으로 구동되는 <Zombie Days>에 실시간 멀티플레이 기능을 도입하려고 해. 
웹 브라우저 환경 특성상 표준 소켓(`import socket`)은 사용할 수 없으므로, 비동기 웹소켓(WebSocket) 통신을 활용한 중앙 서버 방식을 사용할 거야.

기존의 단일 플레이어 로직을 멀티플레이어 환경에 맞게 리팩토링하기 위해 1단계 작업을 수행해 줘.

---

### 1. 플레이어 데이터 구조 분리 및 NetworkPlayer 클래스 생성
- 현재는 플레이어(`Player`) 한 명의 좌표와 상태만 관리하고 있지만, 앞으로 다른 유저들의 정보를 실시간으로 받아 화면에 그려주어야 해.
- 타 유저의 캐릭터를 렌더링할 수 있도록 고유 ID, 좌표(X, Y), 현재 상태(도보, 탑승한 차량 ID, 생존 일수, 애니메이션 프레임 등)를 가지는 `NetworkPlayer` 클래스를 새롭게 정의해 줘.
- 메인 루프에서 내 플레이어뿐만 아니라 전역 딕셔너리(`remote_players = {}`)에 존재하는 다른 플레이어들도 청크 스트리밍 엔진 내부에서 함께 뷰포트 컬링을 거쳐 렌더링되도록 수정해 줘.

### 2. 가상의 네트워크 동기화 함수(Placeholder) 배치
- 아직 실제 서버가 없으므로, 게임의 비동기 메인 루프(`async def main():`) 내부에 주기적으로(예: 1초에 20번, 20Hz) 내 좌표와 스탯을 패킷 형태로 내보내고, 다른 유저의 데이터를 수신했다고 가정하는 더미 함수 `async def sync_network_data():`를 구조적으로 배치해 줘.
- 추후 실제 웹소켓 라이브러리(`python-socketio` 등)를 붙이기 편하도록 확장성 있는 구조로 설계해 줘.

### 3. 멀티플레이 시 고려해야 할 청크 최적화 방향 제안
- 멀티플레이어가 되면 각 유저마다 주변 3x3 청크를 활성화해야 하므로 서버와 클라이언트 간의 데이터 주고받기가 빈번해져.
- 내 플레이어 주변의 좀비 스폰 권한을 동기화하거나, 화면 밖의 멀티플레이어 위치 처리를 효율적으로 하기 위한 아키텍처 힌트를 주석으로 남겨 줘.
