# 개발 지시서: Zombie Days - 웹(HTML5/Pygbag) 구동을 위한 소스코드 리팩토링 (Phase 11)

우리는 현재 개발 중인 Python 기반의 <Zombie Days> 게임을 브라우저에서 '플래시 게임'처럼 즉시 실행할 수 있도록 웹 호환 코드(WebAssembly/Pygbag 기법)로 전환하려고 해. 
현재 오디오(사운드) 기능은 구현되지 않은 상태이므로, 복잡한 사운드 컨텍스트 제한은 제외하고 **'메인 루프의 비동기화'**와 **'자원 로드 안정성'**에 집중하여 코드를 수정해 줘.

아래 요구사항을 반영하여 기존 소스코드를 웹 친화적으로 리팩토링해 줘.

---

### 1. 비동기 메인 루프 (Async Main Loop) 필수 적용
- Pygbag은 웹 브라우저의 메인 스레드가 멈추지 않도록 파이썬 루프를 비동기식으로 제어해야 해.
- 파일 최상단에 `import asyncio`를 추가해 줘.
- 게임의 메인 진입 함수(예: `def main():` 또는 `def run_game():`)를 비동기 함수인 `async def main():` 형태로 변경해 줘.
- 메인 `while True:` 게임 루프 내부의 가장 마지막 줄(보통 `clock.tick(60)` 직후)에 반드시 `await asyncio.sleep(0)`을 삽입하여 브라우저가 화면을 갱신하고 다른 작업을 처리할 수 있는 타이밍을 양보하게 해 줘.
- 프로그램의 최하단 실행부 역시 기존 `main()` 호출 방식에서 `asyncio.run(main())` 형태로 안전하게 감싸서 실행하도록 수정해 줘.

### 2. 웹 환경 자원(Asset) 로딩 및 경로 안전성 확보
- 웹 브라우저 환경(Linux 기반 Wasm)은 파일 경로의 대소문자를 칼같이 구분하므로, 코드 내에서 호출하는 모든 이미지, 폰트 파일명(`assets/...`)의 대소문자가 실제 폴더 내의 파일명과 100% 일치하도록 검증하고 소문자 기반의 상대 경로로 통일해 줘.
- 웹 빌드 시 시스템 폰트가 누락되어 튕기는 현상을 방지하기 위해, `pygame.font.SysFont()` 대신 프로젝트 폴더 내에 포함된 픽셀 폰트 파일(`.ttf`)을 `pygame.font.Font()`로 명시적 로드하도록 처리해 줘.

### 3. 웹 빌드 및 로컬 테스트 자동화 스크립트 제공
- 수정이 완료된 후, 개발자가 터미널에서 즉시 웹 구동 테스트를 해볼 수 있도록 아래의 가이드를 주석이나 README 형태로 코드와 함께 출력해 줘.
  1. `pip install pygbag` 명령어를 통한 빌더 설치 방법
  2. `pygbag main.py` 명령어를 실행하여 로컬 웹 서버(localhost:8000)에서 즉시 테스트하는 방법
  3. 최종 배포용 단일 HTML5 패키지가 생성되는 위치(build/web 폴더) 안내
